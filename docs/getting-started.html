Hexo Theme  ·  v1.x

coldnight

A dark, minimal Hexo theme with a post grid, full-width archive lists, LightGallery integration, and polished code blocks.

Hexo 8 Dark theme LightGallery v2 EJS + SCSS
🗃️

3-column post grid

Responsive grid (3 → 2 → 1 cols) with cover images and reading-time estimates.

📋

Archive / tag / category lists

Year-grouped, date-sorted lists — no pagination required.

🖼️

LightGallery v2

Full-screen image viewer with zoom and thumbnail strip. Auto-mounted on post images.

💻

Code blocks

Language label + one-click copy button. Code blocks are excluded from reading-time estimates.

📌

Configurable sidebar

Recent posts, tag cloud, archive widget. Can be left, right, or hidden.

🔌

Tag plugins

{% gallery %}, {% note %}, {% tabs %}, {% timeline %}, {% spoiler %}, and {% download %} — with full Markdown support inside each.

📖

Table of contents

Auto-generated from post headings. Sticky in the sidebar with scroll-spy active-section highlighting.

📊

Reading progress bar

3px accent-colored bar fixed to the top of the viewport. Fills as the reader scrolls through a post.

🔍

Full-text search

Instant search dropdown in the navbar. Matches titles, content, and tags. Keyboard-navigable with highlight marks on matches.

🔗

Open Graph & SEO

Canonical tag, og:*, twitter:card, article:published_time, and keywords — all wired from post front-matter.

🔁

Related posts

"You might also like" row at the bottom of each post. Scored by shared tags and category at build time — no plugin required.

⭐

Featured / pinned post

Add pinned: true to any post's front-matter to promote it as a full-width hero card above the index grid.

🔖

Links page

A curated link archive at /links/. CSS masonry layout — add entries to a YAML file to grow the collection, no rebuilding templates needed.

🖼️

Showroom page

A paginated project portfolio at /showroom/. 3×3 card grid with 1:1 aspect ratio, gradient overlay, always-visible title, hover subtitle. Each project has its own page.

📐

Mermaid diagrams

Fenced ```mermaid blocks rendered to SVG. All assets self-hosted — no CDN requests.

∑

KaTeX math

$...$ and $$...$$ rendered to HTML at build time. Zero runtime JavaScript — only the KaTeX CSS is served.

Requirements

  • Node.js 18 or later
  • Hexo CLI 8.x (npm install -g hexo-cli)
  • The following Hexo plugins (installed alongside the theme):
    • hexo-renderer-ejs ^2.0
    • hexo-renderer-dartsass ^1.0
    • hexo-renderer-marked ^7.0
    • hexo-generator-archive ^2.0
    • hexo-generator-tag ^2.0
    • hexo-generator-category ^2.0
    • hexo-generator-index ^4.0
    • hexo-generator-search ^2.4 (required for search feature)

Installation

  1. Scaffold a new Hexo site (skip if you already have one): 
    hexo init my-blog
cd my-blog
npm install
  2. Add the theme as a git submodule: 
    git submodule add https://github.com/Cracksoldier/coldnight-theme.git themes/coldnight

    Anyone cloning your site later will need to run git clone --recurse-submodules <url>, or git submodule update --init after a plain clone.

  3. Install required renderers (if not already present): 
    npm install hexo-renderer-ejs hexo-renderer-dartsass hexo-renderer-marked \
  hexo-generator-archive hexo-generator-tag hexo-generator-category \
  hexo-generator-index hexo-generator-search
  4. Enable the theme in your site's _config.yml: 
    theme: coldnight
  5. Set pagination in your site's _config.yml so the index grid is full and archive pages show all posts: 
    index_generator:
  per_page: 9       # 3×3 grid

archive_generator:
  per_page: 0       # no pagination

tag_generator:
  per_page: 0

category_generator:
  per_page: 0
  6. Launch the dev server: 
    hexo server
    Open http://localhost:4000.

Quick start

Theme defaults are already reasonable. The only thing most sites need is a site name and any optional overrides — add them to your site's _config.yml under theme_config::

theme_config:
  navbar:
    title: "My Blog"
    links:
      - { name: Home,    url: / }
      - { name: Archive, url: /archives }

  sidebar:
    position: right

  lightgallery:
    enabled: true

  code:
    copy_button: true

The theme ships with Home, Archive, and About in the navbar by default. Links and Showroom are opt-in — add them to navbar.links only after you've created those pages (see the setup sections below).

Links page

The theme ships with a built-in link repository at /links/ — a single paginated page that displays external links as cards in a responsive CSS masonry layout. New links are added by appending entries to a YAML file; no template changes are needed.

  1. Create the page stub at source/links/index.md: 
    ---
title: Links
layout: links
---

    The layout: links front-matter tells Hexo to use themes/coldnight/layout/links.ejs instead of the generic page.ejs.

  2. Create the data file at source/_data/links.yml with at least one entry: 
    - title:    "Resource Name"
  url:      "https://example.com/"
  abstract: "One or two sentence description."
  3. Add the navbar link in your site's _config.yml under theme_config:: 
    theme_config:
  navbar:
    links:
      - { name: Home,    url: / }
      - { name: Archive, url: /archives }
      - { name: Links,   url: /links }

    Do not edit themes/coldnight/_config.yml directly — it's a git submodule shared by all users. Always override through theme_config: in your site config.

Adding links

Each entry in source/_data/links.yml is one card. Append entries at any time — just run hexo generate (or let the dev server pick up the change) to rebuild.

FieldRequiredDescription
titleYesCard heading
urlYesDestination URL — opens in a new tab
abstractYesOne or two sentence description shown on the card
subtitleNoShort tagline rendered below the title in muted text
thumbnailNoPath or URL to a cover image (16:9 crop). Omit for a text-only card.

Example with all fields:

- title:     "Hexo Documentation"
  subtitle:  "Static site generator"
  url:       "https://hexo.io/docs/"
  abstract:  "The official reference for Hexo — covers installation, configuration, and theme development."
  thumbnail: "/images/links/hexo.png"
💡

Cards without a thumbnail are naturally shorter, which creates the staggered masonry effect. A mix of thumbnail and text-only cards looks better than all-thumbnail or all-text.

Showroom page

The theme includes a built-in project portfolio at /showroom/ — a paginated 3×3 grid of project cards. Each card shows a 1:1 cover image with an always-visible title overlay and a subtitle that appears on hover. Clicking a card navigates to a dedicated project page with the full Markdown content. New projects are added by creating Markdown files; the grid and pagination are handled automatically by a built-in generator.

  1. Create a project page at source/showroom/<slug>/index.md: 
    ---
title:       "My Project"
subtitle:    "A short tagline"
cover_image: /images/showroom/my-project.jpg
layout:      project
date:        2026-01-01
---

Write the project description here in Markdown.

    The layout: project front-matter tells Hexo to render this page with themes/coldnight/layout/project.ejs — a full-width layout with a 16:9 cover image, subtitle, and Markdown body. The page is accessible at /showroom/<slug>/.

  2. Add the cover image to source/images/showroom/. Any image format works; square crops (1:1) look best since the card clips to that ratio, but the full image is shown on the project page at 16:9.
  3. Add the navbar link in your site's _config.yml under theme_config:: 
    theme_config:
  navbar:
    links:
      - { name: Home,     url: / }
      - { name: Archive,  url: /archives }
      - { name: Showroom, url: /showroom }

    Do not edit themes/coldnight/_config.yml directly — it's a git submodule shared by all users. Always override through theme_config: in your site config.

Adding a project

Each project is a Markdown file at source/showroom/<slug>/index.md. Create one any time — just run hexo generate (or let the dev server pick up the change) to rebuild. The grid, pagination, and sort order update automatically.

The slug becomes the URL path: source/showroom/my-cli-tool/index.md is published at /showroom/my-cli-tool/. Use lowercase, hyphen-separated words.

Minimal template:

---
title:       "Project Name"
subtitle:    "One-line tagline"
cover_image: /images/showroom/project-name.jpg
layout:      project
date:        2026-01-15
---

Brief intro paragraph — this becomes the project page body.

## What it does

Write freely using any Markdown: headings, lists, code blocks, tables,
{% note %} callouts, etc.

Place the cover image at the path declared in cover_image. It is cropped to 1:1 on the grid card and displayed at 16:9 on the project page, so an image that reads well at both ratios works best — a wide subject centred in the frame is ideal.

💡

Sort order on the grid is newest-first by date. Set the date to the project's actual creation or release date so the grid reflects a meaningful chronology rather than the order files were added to the repository.

Project front-matter reference

FieldRequiredDescription
titleYesProject name — shown on the card overlay and the project page heading
subtitleYesShort tagline — shown on hover over the card and below the title on the project page
cover_imageYesPath to the cover image. Clipped to 1:1 on the card; shown at 16:9 on the project page.
layoutYesMust be project — routes the page to project.ejs
dateYesControls sort order on the grid (newest first)
ai_assistedNoBare boolean true — shows a blue "AI-assisted" pill badge on the card. Never use a string value.

Pagination

The grid shows 9 projects per page. When there are more than 9, pagination controls appear below the grid linking to /showroom/page/2/, /showroom/page/3/, etc. No configuration is needed — the built-in generator handles all routes automatically.

AI-assisted badge

Add ai_assisted: true (bare YAML boolean) to a project's front-matter to show a blue pill badge on the card. Use only the bare boolean — never a string like "yes" or "true".

💡

The Showroom index (/showroom/) is generated entirely from your project files — there is no source/showroom/index.md to create. Only the individual project pages under source/showroom/<slug>/ are needed.
