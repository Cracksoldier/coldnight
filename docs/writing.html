Writing

How to structure posts and use the theme's Markdown extensions.

Post front-matter

All fields except title and date are optional.

---
title:        My Post Title
date:         2026-01-15
categories:  [Dev]
tags:         [javascript, hexo]
cover_image:  /images/cover.jpg   # optional; falls back to cover.default
excerpt:      "Override the auto-excerpt shown on post cards."
pinned:       true                  # optional; promotes post to featured hero on the index page
series:       "My Series Name"      # optional; groups post into a numbered series nav strip
---
FieldDescription
titleRequired. The post title shown in the header, page <title>, and og:title.
dateRequired. Publication date. Used for archive sorting and article:published_time.
categoriesArray of category names. The first is the primary category used in post cards and related-post scoring.
tagsArray of tag names. Used in the tag cloud widget, tag pages, related-post scoring, and OG keywords.
cover_imagePath to the post's cover image. Used on post cards, the post header, the pinned hero, and as og:image. Falls back to theme.cover.default if omitted.
excerptOverride the auto-excerpt shown on post cards and in og:description. If omitted, Hexo uses the text up to the first <!-- more --> tag, or the start of the post body.
pinnedSet to true to promote this post to the featured hero card on index page 1. See Featured post.
seriesA string that groups this post with others sharing the same value. All matching posts appear in a numbered nav strip above the post body, sorted by date. See Series posts.
💡

You can also use <!-- more --> anywhere in the post body to set the excerpt boundary instead of the front-matter excerpt field.

Footnotes

hexo-renderer-marked supports standard Markdown footnote syntax out of the box. The theme provides matching styles — no plugin or extra config required.

Syntax

Here is a sentence with a footnote.[^1]

A second reference uses the same syntax.[^note]

[^1]: This is the footnote text.
[^note]: Footnote labels can be any string — they render as sequential numbers.
ElementDescription
[^label]Inline reference. Renders as a superscript number linking to the footnote definition at the bottom of the post.
[^label]: textFootnote definition. Must appear somewhere in the post body (typically at the end). The label can be any alphanumeric string.
💡

Footnote labels are for authoring only — they always render as sequential integers (1, 2, 3, …) in the output regardless of the label string you use.

How it works

hexo-renderer-marked transforms [^label] references into <sup class="footnote-ref"><a href="#fn1" id="fnref1">[1]</a></sup> inline, and collects all definitions into a <section class="footnotes"> element at the end of the rendered HTML. The section contains an <hr> (hidden by the theme's CSS — the border-top on .footnotes replaces it) and a numbered <ol>. Each <li> ends with a <a class="footnote-backref">↩</a> that links back to the inline reference.

All styling lives in _typography.scss inside the .post-body, .prose { } block. The inline reference .footnote-ref a is styled as a small superscript in $accent-light. The .footnotes section gets a top border, smaller font size, and muted color to visually separate it from the main post body.

{% gallery %} tag

Renders a responsive photo grid powered by LightGallery. Each image opens in full-screen when clicked.

Syntax

{% gallery [cols] %}
![Caption text](/images/photo1.jpg)
![Another photo](/images/photo2.jpg)
![](/images/photo3.jpg)          # caption is optional
{% endgallery %}
ParameterTypeDefaultDescription
cols number 3 Number of columns in the photo grid. Supported values: 1–6. Each value maps to a dedicated CSS grid rule generated by a SCSS @for loop.

Example

{% gallery 2 %}
![Sunset over the mountains](/images/trip/sunset.jpg)
![Morning fog in the valley](/images/trip/fog.jpg)
{% endgallery %}

How it works

scripts/helpers.js registers gallery as a Hexo block tag plugin. When Hexo encounters {% gallery [cols] %}…{% endgallery %} during rendering, it calls the plugin with the block body as a string. The plugin scans the body for Markdown image syntax (![alt](src)), wraps each image in an anchor tag (<a href="src"><img src="src" alt="alt"></a>), and wraps the entire collection in:

<div class="lg-gallery" data-cols="N">
  <a href="/images/photo1.jpg"><img src="/images/photo1.jpg" alt="Caption text"></a>
  ...
</div>

The cols argument is clamped to 1–6 by the plugin; values outside that range default to 3. On post pages where LightGallery is enabled, source/js/gallery.js queries all .lg-gallery elements on page load and mounts a separate lightGallery(element, { plugins: [...] }) instance on each one. Each gallery block is fully independent — clicking an image in one gallery cannot open images from another.

The CSS grid column count is driven by the data-cols attribute. _components.scss generates rules for all six values via a SCSS @for loop:

@for $i from 1 through 6 {
  &[data-cols="#{$i}"] { grid-template-columns: repeat(#{$i}, 1fr); }
}

On mobile (≤640px) the SCSS overrides all data-cols values to 2 columns regardless of what was specified.

⚠️

lightgallery.enabled must be true in the theme config for gallery clicks to open the lightbox. The grid will still render without it, but clicking images won't open a full-screen viewer.

{% note %} tag

Renders a styled callout box. Markdown is supported inside the tag body.

Syntax

{% note type %}
Content here. **Markdown** is _supported_.
{% endnote %}
TypeColorIconWhen to use
tip Green ✓ Best practices, helpful hints
info Blue ℹ Neutral supplementary information
warning Yellow ⚠ Caveats, deprecated features
danger Red ✕ Breaking changes, data loss risks

Examples

{% note tip %}
Run `hexo clean` before `hexo generate` to avoid stale cache issues.
{% endnote %}

{% note warning %}
This option will be **removed** in a future release.
{% endnote %}

How it works

scripts/helpers.js registers note as a Hexo block tag plugin. The first word after note is the type; the plugin validates it against the four allowed values (tip, info, warning, danger) and renders an unknown type as info. The block body is passed to Hexo's built-in Markdown renderer so that bold, italic, inline code, and other Markdown syntax works inside the callout.

The output is a <div class="note note-{type}"> containing an inline SVG icon (hard-coded per type — no external icon font or image request) and the rendered body wrapped in a <p>:

<div class="note note-tip">
  <svg class="note-icon" ...></svg>
  <p>Run <code>hexo clean</code> before ...</p>
</div>

Each type has its own color scheme defined in _components.scss. note-tip uses green ($success / $success-bg), note-info uses blue ($accent / $info-bg), note-warning uses amber ($amber / $amber-bg), and note-danger uses red ($danger / $danger-bg). All color values are SCSS variables from _variables.scss — never hardcoded.

{% tabs %} tag

Renders a multi-tab content block. Switching between tabs is handled by pure CSS (no JavaScript) using hidden radio inputs. Markdown is fully supported inside each tab panel.

Syntax

{% tabs %}
<!-- tab Tab name -->
Content for the first tab. **Markdown** is _supported_.
<!-- endtab -->
<!-- tab Another tab -->
Content for the second tab.
<!-- endtab -->
{% endtabs %}

Example — code in multiple languages

{% tabs %}
<!-- tab JavaScript -->
```js
console.log('hello world')
```
<!-- endtab -->
<!-- tab Python -->
```py
print('hello world')
```
<!-- endtab -->
<!-- tab Rust -->
```rust
println!("hello world");
```
<!-- endtab -->
{% endtabs %}
ℹ️

Up to 10 tabs are supported per block. Tab names can contain spaces but must not contain -->.

How it works

scripts/helpers.js registers tabs as a Hexo block tag plugin. It parses <!-- tab Name --> … <!-- endtab --> markers to split the block into named panels. For each tab it emits a hidden <input type="radio"> with a unique ID, a matching <label> in the tab nav bar, and a <div class="tabs__panel"> for the content. Each panel body is passed through Hexo's synchronous Markdown renderer so fenced code blocks and other syntax work normally.

The "active tab" state is driven entirely by CSS: the checked radio input selects both the active label (via :checked ~ .tabs__nav .tabs__label:nth-child(N)) and the active panel (via :checked ~ .tabs__panels .tabs__panel:nth-child(N)). All non-active panels are display: none. Styles live in _components.scss under // ─── Tabs.

Image captions

When image_captions: true in the theme config (enabled by default), images written as standalone paragraphs are automatically upgraded to <figure> + <figcaption> elements at build time. The caption text is taken from the Markdown alt attribute.

Syntax

![This text becomes the caption](/images/photo.jpg)

Renders as:

<figure>
  <img src="/images/photo.jpg" alt="This text becomes the caption">
  <figcaption>This text becomes the caption</figcaption>
</figure>
💡

Images with an empty alt attribute (![](/images/photo.jpg)) are left as plain <img> elements — no caption is added. This is useful for decorative images that shouldn't have a caption.

The conversion is applied by the after_render:html filter in scripts/helpers.js — it runs on every page after HTML rendering. Set image_captions: false in the theme config to disable it.
