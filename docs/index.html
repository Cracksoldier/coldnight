Hexo Theme  ·  v1.x

coldnight

A dark, minimal Hexo theme with a post grid, full-width archive lists, LightGallery integration, and polished code blocks.

Hexo 8 Dark theme LightGallery v2 EJS + SCSS
🗃️

3-column post grid

Responsive grid (3 → 2 → 1 cols) with cover images and reading-time estimates.

📋

Archive / tag / category lists

Year-grouped, date-sorted lists — no pagination required.

🖼️

LightGallery v2

Full-screen image viewer with zoom and thumbnail strip. Auto-mounted on post images.

💻

Code blocks

Language label + one-click copy button via highlight.js.

📌

Configurable sidebar

Recent posts, tag cloud, archive widget. Can be left, right, or hidden.

🔌

Tag plugins

{% gallery %} photo grids and {% note %} callout boxes.

📖

Table of contents

Auto-generated from post headings. Sticky in the sidebar with scroll-spy active-section highlighting.

📊

Reading progress bar

3px accent-colored bar fixed to the top of the viewport. Fills as the reader scrolls through a post.

🔍

Full-text search

Instant search dropdown in the navbar. Matches titles, content, and tags. Keyboard-navigable with highlight marks on matches.

🔗

Open Graph & SEO

Canonical tag, og:*, twitter:card, article:published_time, and keywords — all wired from post front-matter.

🔁

Related posts

"You might also like" row at the bottom of each post. Scored by shared tags and category at build time — no plugin required.

⭐

Featured / pinned post

Add pinned: true to any post's front-matter to promote it as a full-width hero card above the index grid.

Requirements

  • Node.js 18 or later
  • Hexo CLI 8.x (npm install -g hexo-cli)
  • The following Hexo plugins (installed alongside the theme):
    • hexo-renderer-ejs ^2.0
    • hexo-renderer-dartsass ^1.0
    • hexo-renderer-marked ^7.0
    • hexo-generator-archive ^2.0
    • hexo-generator-tag ^2.0
    • hexo-generator-category ^2.0
    • hexo-generator-index ^4.0
    • hexo-generator-search ^2.4 (required for search feature)

Installation

  1. Scaffold a new Hexo site (skip if you already have one): 
    hexo init my-blog
cd my-blog
npm install
  2. Copy the theme into the themes/ directory: 
    # Option A — clone directly
git clone https://github.com/<your-user>/coldnight themes/coldnight

# Option B — copy the folder manually
cp -r /path/to/coldnight themes/coldnight
  3. Install required renderers (if not already present): 
    npm install hexo-renderer-ejs hexo-renderer-dartsass hexo-renderer-marked \
  hexo-generator-archive hexo-generator-tag hexo-generator-category \
  hexo-generator-index hexo-generator-search
  4. Enable the theme in your site's _config.yml: 
    theme: coldnight
  5. Set pagination in your site's _config.yml so the index grid is full and archive pages show all posts: 
    index_generator:
  per_page: 9       # 3×3 grid

archive_generator:
  per_page: 0       # no pagination

tag_generator:
  per_page: 0

category_generator:
  per_page: 0
  6. Launch the dev server: 
    hexo server
    Open http://localhost:4000.

Quick start

Here is the minimal themes/coldnight/_config.yml you need to get a working site:

navbar:
  title: "My Blog"
  links:
    - { name: Home,    url: / }
    - { name: Archive, url: /archives }

sidebar:
  position: right

lightgallery:
  enabled: true

code:
  copy_button: true

Navbar

Controls the top navigation bar. Links accept any absolute path or external URL.

navbar:
  title: "My Blog"        # site name shown left of the navbar
  links:
    - name: Home
      url:  /
    - name: Archive
      url:  /archives
    - name: About
      url:  /about

Sidebar

The sidebar appears only on the two-column layout (index and post pages).

KeyTypeDefaultDescription
sidebar.position string right left | right | hidden. Use hidden to give the post body the full width.
sidebar.widgets array — Ordered list of widget names to render. Available: toc, recent_posts, tags, archives, about. The toc widget only renders on post pages and is hidden when the post has no headings. 
sidebar:
  position: right   # left | right | hidden
  widgets:
    - toc           # Table of contents (post pages only)
    - recent_posts
    - tags
    - archives

Social links

Displayed in the footer. Leave a value empty to hide that icon.

social:
  github:  "your-username"   # → https://github.com/your-username
  twitter: "your-handle"     # → https://twitter.com/your-handle
  rss:     true              # show RSS feed link (/atom.xml)

Cover images

KeyTypeDefaultDescription
cover.default string "" Absolute path to a fallback image used when a post has no cover_image in its front-matter.
cover.aspect_ratio string "16/9" CSS aspect-ratio value applied to post-card thumbnails. 
cover:
  default:      "/images/default-cover.jpg"
  aspect_ratio: "16/9"

Code blocks

KeyTypeDefaultDescription
code.copy_button boolean true Show a copy-to-clipboard button in the code block toolbar. Excludes line numbers from the copied text. Uses navigator.clipboard with an execCommand fallback for non-HTTPS contexts.
code.language_label boolean true Display the detected language name in the top-right corner of each code block.
ℹ️

The site's _config.yml must use syntax_highlighter: highlight.js with hljs: true. The copy button targets td.code specifically to avoid copying gutter line numbers.

LightGallery

LightGallery v2 JS and CSS are loaded via jsDelivr CDN only on post pages when enabled — no CDN requests on index, archive, tag, or category pages.

KeyTypeDefaultDescription
lightgallery.enabled boolean true Include LightGallery CDN assets. Disable for sites with no images or that need no external requests.
lightgallery.auto_mount boolean true Auto-wrap every .post-body img (not tagged .no-gallery) as a lightbox item on click. A single LightGallery instance is created on page load; clicking an image opens it at the correct index.
lightgallery.zoom boolean true Enable the LightGallery zoom plugin.
lightgallery.thumbnail boolean true Enable the thumbnail strip plugin at the bottom of the lightbox.

Post grid

Controls the layout of the index page. In grid mode, per_page is automatically set to columns × rows. In list mode (columns: 1), per_page is left untouched so the value in the site's _config.yml applies.

KeyTypeDefaultDescription
grid.columns number 3 Number of columns on the index page. Set to 1 to switch to a horizontal list view with thumbnails. Responsive: tablet uses ceil(columns/2), mobile always collapses to 1.
grid.rows number 3 Grid mode only. Rows per page; per_page is auto-set to columns × rows. e.g. columns: 2, rows: 4 → 8 posts per page. Ignored in list mode — set per_page in the site's _config.yml instead. 
grid:
  columns: 3   # 1 = list view, 2–6 = grid
  rows:    3   # grid only: per_page = columns × rows; ignored in list mode

Table of contents

Auto-generates a sticky TOC in the sidebar from post headings. Add toc to sidebar.widgets to display it. The widget silently renders nothing on posts with no headings.

KeyTypeDefaultDescription
toc.enabled boolean true Enable the TOC widget and load toc.js on post pages. Set to false to disable both.
toc.max_depth number 3 Maximum heading level to include. 2 = ## headings only; 3 = ## and ###. H3 entries are indented in the list. 
toc:
  enabled:   true
  max_depth: 3   # 2 = h2 only, 3 = h2 + h3
ℹ️

Scroll-spy uses IntersectionObserver to highlight the active section as the reader scrolls. The TOC is collapsible on mobile via a toggle button.

Misc toggles

KeyTypeDefaultDescription
reading_time boolean true Show an estimated reading time ("N min read") on post cards and post headers. Calculated at ~200 wpm. Code blocks are excluded from the word count so they don't inflate the estimate.
progress_bar boolean true Show a 3px accent-colored reading progress bar fixed to the top of the viewport on post pages. Fills left-to-right as the reader scrolls. No effect on other page types.
related_posts boolean true Show a "You might also like" section of up to 3 post cards at the bottom of each post page. Posts are scored by shared tags (+2 pts each) and the same primary category (+1 pt). Set to false to hide the section on all posts.
sponsor.enabled boolean false Show a sponsor / "Buy me a coffee" link in the post footer.
sponsor.label string "Buy me a coffee" Button label text.
sponsor.url string "" Link destination (Ko-fi, GitHub Sponsors, etc.).

Search

Full-text search of post titles, content, and tags via a dropdown in the navbar. Requires hexo-generator-search and a search: block in the site _config.yml.

Add to the site-level _config.yml:

search:
  path:    search.json
  field:   post
  content: true
KeyTypeDefaultDescription
search.enabled boolean true Show the search input in the navbar. Set to false to hide it and skip loading search.js.

Open Graph / SEO

All Open Graph, Twitter Card, and SEO meta tags are emitted from _partial/head.ejs automatically — no extra configuration is required. The following fields are populated from post front-matter and site config:

Meta tagSource
og:title / twitter:titlepage.title, falls back to config.title
og:description / twitter:description / meta descriptionpage.description → page.excerpt (strips HTML) → config.description
og:image / twitter:imagecover_image front-matter → theme.cover.default; resolved to an absolute URL using config.url
og:typearticle on post pages, website everywhere else
og:site_nameconfig.title
canonicalpage.permalink
article:published_time / article:authorpage.date / config.author — post pages only
twitter:sitetheme.social.twitter (prefixed with @); omitted when blank
meta keywordsPost tags joined by comma, falls back to config.keywords
💡

Set url: in the site _config.yml to your production domain (e.g. https://example.com) so that og:image and canonical links are absolute.

Related posts

When related_posts: true, a "You might also like" section renders up to 3 post cards at the bottom of every post page (below the post footer, above </main>). The scoring runs entirely at build time inside post.ejs — no plugin is required.

KeyTypeDefaultDescription
related_posts boolean true Show the "You might also like" section. Set to false to hide it on all posts.

Scoring algorithm

Every other post is scored against the current post, and the top 3 non-zero scores are shown:

  • +2 pts per tag that appears in both posts
  • +1 pt if both posts share the same primary category

Posts with a score of 0 are excluded. The section is hidden entirely when no candidates score above 0. The cards reuse the same _partial/post-card.ejs partial and the existing .post-grid CSS (fixed at 2 cols desktop and tablet, 1 mobile — 3 columns was too narrow inside the post body's ~700px width). The section heading is <h3> to avoid conflicting with post body ## headings at the same outline level.

Featured / Pinned post

Adding pinned: true to a post's front-matter promotes it to a full-width hero card above the index grid on page 1. No theme config toggle is needed — the feature is active whenever at least one post is pinned, and invisible otherwise.

BehaviourDetail
Which post becomes hero?The most recently dated post with pinned: true. If several posts are pinned, only the newest is shown as hero; the others appear in the grid normally.
Page 1Hero card renders above the grid. The pinned post is removed from the grid on this page to avoid duplication.
Page 2+Hero is hidden. The pinned post reappears in its chronological grid slot.
No pinned postIndex page renders exactly as before — no change.

The hero partial is _partial/pinned-post.ejs. It shows a 45%-wide cover panel on the left, a "Featured" badge, category, reading time, title, excerpt, date, and a "Read more" link. On mobile (<640px) the cover stacks above the content. .pinned-post has min-height: 200px to guarantee visual weight with minimal content and to anchor the cover panel height via flexbox stretch. Styles live in _components.scss under // ─── Pinned / Featured post.

💡

Give the pinned post a cover_image for the best hero appearance — without a cover the hero displays content-only with a blue accent border.

Post front-matter

All fields except title and date are optional.

---
title:        My Post Title
date:         2026-01-15
categories:  [Dev]
tags:         [javascript, hexo]
cover_image:  /images/cover.jpg   # optional; falls back to cover.default
excerpt:      "Override the auto-excerpt shown on post cards."
pinned:       true                  # optional; promotes post to featured hero on the index page
---
💡

You can also use <!-- more --> anywhere in the post body to set the excerpt boundary instead of the front-matter excerpt field.

{% gallery %} tag

Renders a responsive photo grid powered by LightGallery. Each image opens in full-screen when clicked.

Syntax

{% gallery [cols] %}
![Caption text](/images/photo1.jpg)
![Another photo](/images/photo2.jpg)
![](/images/photo3.jpg)          # caption is optional
{% endgallery %}
ParameterTypeDefaultDescription
cols number 3 Number of columns in the photo grid. Supported values: 1–6. Each value maps to a dedicated CSS grid rule.

Example

{% gallery 2 %}
![Sunset over the mountains](/images/trip/sunset.jpg)
![Morning fog in the valley](/images/trip/fog.jpg)
{% endgallery %}
⚠️

lightgallery.enabled must be true in the theme config for gallery clicks to open the lightbox. The grid will still render without it, but clicking images won't open a full-screen viewer.

Page layouts

The theme uses two distinct page shells:

Two-column shell

Used by the index and post pages. A CSS Grid layout (65fr 35fr) with .main-content and .sidebar. Setting sidebar.position: hidden collapses the sidebar and gives the body the full width.

Full-width shell

Used by archive, tag, category, and static page layouts. A single .archive-wrapper centered at max-width: 1100px with no sidebar. Posts are grouped by year, sorted newest-first, in a compact list row showing date, title, category, and reading time.

Layout files

FileShellDescription
index.ejsTwo-columnHome page with the 3-column post grid (9 per page)
post.ejsTwo-columnIndividual post with cover image, metadata, and body
archive.ejsFull-widthAll posts as a year-grouped list
tag.ejsFull-widthPosts filtered by a single tag
category.ejsFull-widthPosts filtered by a single category
page.ejsFull-widthStatic pages (About, etc.) — no post metadata
404.ejsFull-widthCustom 404 page

Static pages

Create static pages with hexo new page:

hexo new page about

This creates source/about/index.md. The page is rendered with layout/page.ejs (full-width shell, no post metadata). You can add any Markdown content, including {% note %} callouts.

ℹ️

Add the page to navbar.links in the theme config so it appears in the navigation bar.

UI features

Table of contents

When toc.enabled: true and toc is listed in sidebar.widgets, a sticky Contents widget appears in the post sidebar. It is auto-generated at build time from the post's ## and ### headings (Hexo assigns id attributes to every heading automatically). Posts with no headings render no widget.

On the client side, source/js/toc.js uses IntersectionObserver to highlight the active TOC link as each section scrolls into the top 35% of the viewport. On mobile the widget includes a toggle button that collapses/expands the list. Styles live in _components.scss under .widget-toc__toggle, .toc-list, and .toc-link.

Reading progress bar

When progress_bar: true, a 3px bar is injected at the very top of post pages (above the skip-nav link, z-index: 6 — above the sticky navbar). It fills left-to-right as the reader scrolls, reaching 100% at the bottom of the page. The bar has pointer-events: none so it never blocks clicks.

source/js/reading-progress.js updates the bar width on every passive scroll event using scrollY / (scrollHeight - clientHeight). The script and the bar element are both excluded from non-post pages.

Back-to-top button

A circular floating button appears at the bottom-right of every page once the reader scrolls past one viewport height. Clicking it smoothly scrolls back to the top. It is always enabled — no configuration required.

The button uses opacity + visibility: hidden when not visible so it is excluded from keyboard tab order. Styles live in _components.scss under .back-to-top; the script is source/js/back-to-top.js, loaded via _partial/footer.ejs on every page.

Search

When search.enabled: true, a 200px search input appears in the navbar and at the top of the mobile nav drawer. On first focus, source/js/search.js lazily fetches /search.json (generated by hexo-generator-search) and caches it. Both inputs share the same data fetch — focusing the mobile input while the desktop fetch is in-flight does not start a second request. Results appear in an absolute-positioned dropdown with up to 8 matches.

Matching is multi-term: all space-separated words must appear somewhere in the post's title, content, or tags. Matched substrings are wrapped in <mark>. Keyboard navigation: ↓ / ↑ move focus between result links; Escape closes the dropdown and returns focus to the input. Clicking outside also closes it. Styles live in _components.scss under .search-wrap, .search-input, .search-results, and .search-result-item.

Related posts

When related_posts: true, a "You might also like" heading and a row of up to 3 post cards appears at the bottom of every post page. The candidates are scored at build time by shared tags and category (see Related posts configuration). The section is omitted entirely when no post scores above 0. Cards reuse _partial/post-card.ejs inside a fixed 2-column .post-grid. Styles live in _layout.scss under .related-posts and .related-posts__heading.

Featured / pinned post

When a post has pinned: true in its front-matter, index.ejs detects it at build time and renders a _partial/pinned-post.ejs hero card above the post grid on page 1. The pinned post is filtered out of the grid on that page to avoid duplication. On page 2+ the hero is hidden and the post appears in its normal chronological slot. See Featured / Pinned post for full behaviour details.

CSS pipeline

All styles are written in SCSS and compiled by hexo-renderer-dartsass (Dart Sass). The entry point is themes/coldnight/source/css/style.scss, which @uses the partials in dependency order. Each partial declares its own variable dependency via @use 'variables' as *; at the top.

FileContents
_variables.scssAll color, spacing, typography, and breakpoint variables. Edit this file to retheme the entire site.
_base.scssCSS reset, body defaults, scrollbar
_typography.scssPost body typography — headings, lists, blockquotes, tables
_layout.scssPage shell grids (two-column, archive), post grid, archive list rows, sidebar, .post-cover image
_components.scssNavbar, footer, post cards, pagination, note callouts, sidebar widgets, gallery grid, back-to-top button, reading progress bar, TOC widget
_code.scssCode block toolbar, language label, copy button
_lightgallery.scssLightGallery overrides to match the dark theme
💡

Never hardcode color values in partials — always reference a variable from _variables.scss. This ensures a single edit recolors the whole theme.

Deploying to GitHub Pages

Option A — GitHub Actions (recommended)

Create .github/workflows/pages.yml in your repository:

name: Deploy to GitHub Pages

on:
  push:
    branches: [main]

permissions:
  contents: read
  pages:    write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
      - run: npm ci
      - run: npx hexo generate
      - uses: actions/upload-pages-artifact@v3
        with:
          path: public

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name:  github-pages
      url:   ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4

Then in your repo: Settings → Pages → Source → select GitHub Actions.

ℹ️

Set url in your site's _config.yml to your Pages URL (https://username.github.io or https://username.github.io/repo-name) so all asset paths resolve correctly.

Option B — gh-pages branch (hexo-deployer-git)

# Install the deployer plugin
npm install hexo-deployer-git --save

# Add to _config.yml
deploy:
  type:   git
  repo:   https://github.com/username/username.github.io.git
  branch: gh-pages

# Deploy
hexo clean && hexo deploy

Deploying to GitLab Pages

Create .gitlab-ci.yml in the repository root:

image: node:20-alpine

pages:
  stage: deploy
  script:
    - npm ci
    - npx hexo generate
    - mv public public_html    # GitLab Pages requires this name
    - cp -r public_html public  # keep 'public' for the artifact
  artifacts:
    paths:
      - public
  only:
    - main
💡

GitLab Pages serves from the public/ artifact path. Hexo already generates into public/, so no extra config is needed beyond the CI file above.
