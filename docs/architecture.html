Layouts & Structure

How the theme's EJS templates, page shells, and JavaScript features are organized and implemented.

Page layouts

The theme uses two distinct page shells, each optimized for its content type:

Two-column shell

Used by the index and post pages. A CSS Grid layout (65fr 35fr) places .main-content on the left and .sidebar on the right (or left, or hidden). Setting sidebar.position: hidden in the theme config collapses the sidebar column and gives the body full width. The body element is display: flex; flex-direction: column; min-height: 100vh; the .page-wrapper grid container has flex: 1 so it expands to push the footer to the bottom of the viewport.

Full-width shell

Used by archive, tag, category, and static page layouts. A single .archive-wrapper with width: 100%; max-width: 1100px; margin: 0 auto — no sidebar. Posts are grouped by year, sorted newest-first, in a compact list row showing date, linked title, category pill, and reading time. The .archive-wrapper also has flex: 1 for the same footer-pinning reason.

Each layout file is a complete HTML document that includes shared fragments via Hexo's partial() helper: _partial/head, _partial/header, _partial/footer, and so on. The page object (Hexo's built-in page context) and theme (the deserialized themes/coldnight/_config.yml) are available in every template without any extra setup.

Static pages

Create static pages with hexo new page:

hexo new page about

This creates source/about/index.md. The page is rendered with layout/page.ejs — the full-width shell with no post metadata (no date, author, reading time, tags, or related-posts section). Any Markdown content is valid, including {% note %} callouts and {% gallery %} blocks.

ℹ️

Add the page to navbar.links in the theme config so it appears in the navigation bar.

UI features

The following features are implemented as client-side JavaScript loaded on the appropriate page types. All scripts are plain vanilla JS with no dependencies — no framework, no bundler.

Table of contents

When toc.enabled: true and toc is listed in sidebar.widgets, a sticky Contents widget appears in the post sidebar. It is built from the post's ## and ### headings at build time via the render_toc() helper. Heading text and IDs are HTML-escaped before output so titles containing <, >, or & render correctly. Posts with no qualifying headings render no widget at all — the helper returns an empty string.

On the client side, source/js/toc.js is loaded whenever toc.enabled is true (no sidebar-visibility guard). It uses IntersectionObserver with rootMargin: '0px 0px -65% 0px' to fire when a heading enters the top 35% of the viewport, toggling the active class on the matching .toc-link. It queries .toc-link globally — so scroll-spy highlights work for both the sidebar widget and the mobile drawer simultaneously. The active link uses $accent-light (not $accent) to meet WCAG AA contrast on the dark sidebar background. The widget's collapse/expand toggle sets the hidden attribute on the list container and flips aria-expanded — no class toggling, no inline style. The CSS chevron rotation is handled purely by [aria-expanded="false"] svg { transform: rotate(180deg) }. See TOC configuration for the full implementation detail including the mobile drawer.

Reading progress bar

When progress_bar: true, a 3px accent-colored bar is fixed to the very top of the viewport on post pages. It fills left-to-right as the reader scrolls, reaching 100% at the bottom of the content.

Implementation — layout/post.ejs injects a <div id="reading-progress" class="reading-progress"> as the first child of <body>, before the skip-nav link. Its CSS position is fixed; top: 0; z-index: 6, placing it above the sticky navbar (z-index 5). pointer-events: none prevents it from intercepting any clicks. source/js/reading-progress.js attaches a passive scroll listener on window that computes the scroll percentage and sets it as the element's width:

const pct = scrollY / (document.body.scrollHeight - window.innerHeight) * 100
bar.style.width = Math.min(pct, 100) + '%'

The passive event listener flag ({ passive: true }) tells the browser the handler will never call preventDefault(), allowing it to optimize scrolling performance. The script and the bar element are both omitted entirely on non-post pages — they are only emitted by post.ejs when theme.progress_bar is true.

Back-to-top button

A circular floating button appears at the bottom-right of every page once the reader scrolls past one full viewport height. Clicking it smoothly scrolls back to the top using the native window.scrollTo({ top: 0, behavior: 'smooth' }). It is always enabled — no configuration toggle exists.

Implementation — source/js/back-to-top.js is loaded via _partial/footer.ejs on every page. It attaches a passive scroll listener on window that toggles the back-to-top--visible modifier class on #back-to-top once scrollY > window.innerHeight. The button uses opacity + visibility: hidden (not display: none) when invisible — this keeps it in the layout flow and, crucially, excludes it from the keyboard tab order when hidden (a visibility: hidden element cannot receive focus). Styles live in _components.scss under .back-to-top.

Heading anchor links

On post pages, every h2 and h3 in the post body gets a # anchor link injected beside it. The link is hidden by default and revealed with a CSS opacity transition when the reader hovers the heading. Clicking it copies the full section URL to the clipboard (toast confirmation) rather than navigating — matching the UX of Notion, GitHub Docs, and Medium.

Implementation — injected by source/js/copy-code.js inside its existing DOMContentLoaded callback. It queries .post-body h2[id], .post-body h3[id] and appends <a class="heading-anchor" href="#id" aria-hidden="true" tabindex="-1">#</a> to each. A click listener on each anchor calls e.preventDefault(), builds the URL as window.location.origin + pathname + '#' + id, and delegates to the shared writeToClipboard() / showToast() helpers. The aria-hidden and tabindex="-1" keep the anchor out of the accessibility tree and keyboard tab order. Styles live in _components.scss under // ─── Heading anchors.

Search

A 200px text input in the navbar (and a full-width input in the mobile drawer) provides instant full-text search across all post titles, content, and tags. Results appear in an absolute-positioned dropdown below the input with up to 8 matches, highlighted with <mark> spans. All output — including result anchor href attributes — is passed through esc() to prevent XSS. The mobile drawer (#mobile-nav) starts with aria-hidden="true"; nav.js flips it on open/close so screen readers never traverse a closed drawer. Press / anywhere on the page to focus the search input instantly; press ? to open a keyboard shortcuts modal. See Search configuration for the complete implementation detail including lazy fetch, factory pattern, and keyboard navigation.

Dropdown CSS — .search-results is anchored right: 0 with min-width: 320px so it extends leftward into the page rather than off the right viewport edge. The .open modifier applies margin-top: -1px to overlap the input's bottom border; the dropdown's z-index: 20 wins, collapsing two adjacent borders into one clean line. The top-right corner is squared where it meets the input; the top-left keeps the theme radius. .search-input:focus + .search-results.open promotes the full border-color to $border-focus, and :focus:has(+ .search-results.open) squares the input's bottom corners so the pair reads as one connected widget. Result items are display: block (they are <a> tags) so the $accent-glow hover background fills the full row. mark elements have background: none to suppress the browser's default yellow — matched terms appear as bold $accent-light text instead.

Archive filter chips

The archive page shows a row of pill-shaped filter chips above the year-grouped list. Clicking a chip filters posts by category or tag client-side — no page load required. Because archive_generator.per_page: 0 puts all posts into page.posts, the chip set and filter logic are always complete.

Data model — the <% %> block at the top of archive.ejs collects unique categories and tags from page.posts via Set-based deduplication, sorts both arrays alphabetically, then renders one chip per value. Each <li class="archive-item"> carries data-category (primary category name or "") and data-tags (pipe-separated tag names or ""). Pipe (|) is used instead of a space so tag names containing spaces work correctly.

Chip markup — each <button class="archive-filter-chip"> stores data-filter-type ("all", "category", or "tag") and data-filter-value. Category chips show the bare name; tag chips are prefixed with #. The chip bar is wrapped in role="group" aria-label="Filter posts".

Implementation — source/js/archive-filter.js is a self-contained IIFE loaded only on the archive page. On each chip click it: (1) moves the archive-filter-chip--active class to the clicked chip and sets aria-pressed="true" on it / aria-pressed="false" on all others (exclusive — one active filter at a time); (2) sets the hidden attribute on each .archive-item that doesn't match the active filter; (3) checks each .archive-year-group and sets its hidden attribute if all of its items are hidden, collapsing empty year headings automatically. The hidden attribute is used throughout (not display:none) for accessible, style-decoupled visibility. Each chip carries aria-pressed in the HTML so screen readers announce the active filter state without relying solely on the visual accent colour. Styles live in _layout.scss under // ─── Archive filter chips.

External link indicator

When external_links: true (the default), every author-written link in a post body that points to an external domain automatically receives target="_blank" and rel="noopener noreferrer", and a small ↗ icon appears after the link text to signal to readers that the link leaves the site.

Why after_post_render, not after_render:html — all theme-owned external links (social icons, sponsor button, footer) already carry their own target and rel attributes in the EJS templates. Running the filter on the full page HTML would spuriously inject the ↗ icon onto those links. after_post_render receives only data.content — the rendered Markdown fragment before layout injection — so every <a> it sees is author-written post content.

Implementation — scripts/helpers.js registers an after_post_render filter that regex-replaces opening <a href="https?://..."> tags, appending target="_blank" rel="noopener noreferrer". Three skip conditions apply in order: (1) link already has a target attribute (author-configured); (2) link has a download attribute ({% download %} tag output); (3) the link's hostname matches hexo.config.url (internal absolute URL). The ↗ icon is rendered purely via CSS — _typography.scss adds a[target="_blank"]::after { content: " ↗"; font-size: 0.75em; opacity: 0.6 } inside the .post-body, .prose block, so the icon inherits the link's $accent-light color automatically with no extra markup. Set external_links: false in the theme config to disable both the attribute injection and the icon.

Related posts

A "You might also like" row of up to 3 post cards appears at the bottom of every post page. The candidates are selected and scored entirely at build time — no runtime JS is involved. See Related posts configuration for the scoring algorithm and implementation detail.

Featured / pinned post hero

A post with pinned: true in its front-matter is promoted to a full-width hero card above the index grid on page 1. The feature is detected and rendered at build time in index.ejs. See Featured post configuration for the detection, deduplication, and layout implementation.

Mermaid diagrams

When mermaid.enabled: true, fenced ```mermaid blocks are converted to <div class="mermaid"> at build time and rendered as SVG diagrams by the vendored Mermaid JS library client-side.

Build-time transform — Hexo's highlight.js renderer wraps the block in <figure class="highlight plaintext"> with <code class="hljs mermaid"> inside. The theme's after_render:html filter scans every <figure>; when the inner <code> carries the mermaid class, the filter HTML-decodes the block source and replaces the whole <figure> with <div class="mermaid">decoded source</div>. The most important decode is <br> → \n: highlight.js encodes line breaks as <br>, but Mermaid's parser requires literal newlines as statement separators.

Client-side rendering — Mermaid JS is vendored under themes/coldnight/source/vendor/mermaid/ (ESM build, chunked). It is injected as <script type="module"> at the bottom of post.ejs only when mermaid.enabled is true. mermaid.initialize({ startOnLoad: true, theme: '...' }) renders all .mermaid divs on page load. The theme value is validated against /^[a-z]+$/ before injection to prevent code injection from a malformed config string. See Mermaid configuration.

KaTeX math

When math.enabled: true, $...$ and $$...$$ LaTeX delimiters in post Markdown are converted to KaTeX HTML at hexo generate time — zero JavaScript on the page.

Two-filter pipeline — A before_post_render filter replaces math delimiters with HTML placeholder tags (<div class="katex-d" data-e="…"> and <span class="katex-i" data-e="…">) before the Markdown renderer runs. The LaTeX expression is stored HTML-escaped in data-e so it survives Markdown processing unchanged. A combined regex with leftmost-wins semantics matches <hexoPostRenderCodeBlock> regions (Hexo's pre-rendered code block marker) and inline code spans first, skipping them entirely, and only then processes math delimiters outside those protected regions. An after_post_render filter then finds each placeholder, decodes the expression, calls katex.renderToString(), and replaces the placeholder with the output. A figure-skip guard in the after-render regex protects any placeholders that somehow ended up inside a <figure> block.

CSS and assets — _partial/head.ejs emits a <link> to /vendor/katex/katex.min.css on post pages only when math.enabled is true. All KaTeX font files (60 files) are self-hosted under themes/coldnight/source/vendor/katex/fonts/ — no CDN, no runtime network requests. Output uses KaTeX's default htmlAndMathml mode: visual HTML plus a <math> element for screen readers. See KaTeX configuration.

{% timeline %} tag

A build-time block tag plugin for vertical timelines — changelogs, career histories, project journals. Zero runtime cost: the entire output is static HTML generated at hexo generate time.

Syntax — entries are delimited by <!-- entry DATE :: TITLE --> / <!-- endentry --> HTML comment markers inside a {% timeline %}…{% endtimeline %} block. The :: separator splits the date label from the heading; both are optional. Order is author-controlled — no automatic sorting. The block body is passed through Hexo's synchronous Markdown renderer (renderSync) with a try/catch fallback to a <pre>-escaped literal, identical to the pattern used by {% note %} and {% tabs %}. If no valid entries are found the tag emits nothing.

Output structure — the tag emits a <div class="timeline"> wrapper containing one .timeline__entry per parsed entry. Each entry holds a .timeline__marker (a 12px accent-coloured dot), a .timeline__header with optional <time class="timeline__date"> and <span class="timeline__title">, and a .timeline__body with the rendered Markdown. The vertical connecting line is a CSS ::before pseudo-element on .timeline, positioned absolutely to thread through the centre of every dot. All styles live in _components.scss under // ─── Timeline. See {% timeline %} writing guide for syntax details and examples.

Mobile TOC drawer

On viewports ≤640px the sidebar is CSS-hidden (.sidebar { display: none }), leaving post readers with no way to navigate long articles. The mobile TOC drawer solves this by making the existing build-time TOC accessible via a floating button and a bottom-sheet overlay.

Build time — layout/_partial/toc-drawer.ejs is rendered in post.ejs inside the same theme.toc.enabled gate as the sidebar widget. It calls render_toc(page.content) a second time (the same helper, pure build-time, no cost). If the result is empty it renders nothing. Otherwise it emits a .toc-fab button (id="toc-drawer-btn", aria-expanded="false", aria-controls="toc-drawer") and a .toc-drawer overlay + panel (role="dialog", aria-modal="true", initially hidden).

CSS — .toc-fab is display: none by default and only shown via @media (max-width: $bp-mobile). It is positioned fixed; bottom: 80px; right: $sp-4; z-index: 30 — above the back-to-top button (64px) and below the drawer overlay (z-index 40/41). The panel slides up with a CSS @keyframes toc-slide-up animation; the backdrop fades in with @keyframes toc-fade-in. The drawer uses the hidden attribute (not display: none) for toggling — this is consistent with the rest of the theme and avoids fighting the animation.

Client side — source/js/toc-drawer.js is a self-contained IIFE loaded alongside toc.js whenever toc.enabled is true. It wires up four close triggers: overlay click, close-button click, Escape key, and click on any .toc-link. Opening the drawer sets document.body.style.overflow = 'hidden' to prevent background scroll; closing restores it. Focus management: opening moves focus to the close button; closing returns it to the FAB. Because toc.js queries .toc-link globally, scroll-spy active highlighting works for drawer links without any modification to toc.js.

Sticky post title

When sticky_title: true, the post's <h1> heading is mirrored into the navbar once it scrolls out of view. This gives readers a persistent orientation anchor on long posts without duplicating HTML at build time.

Implementation — source/js/post-title.js is a defer-loaded IIFE that runs only on post pages (gated in post.ejs by theme.sticky_title). On load it:

  1. Queries .post-title (the <h1>) and .navbar__inner. Returns early if either is absent.
  2. Creates a <span class="navbar__post-title">, sets its textContent to the heading's text, and inserts it after .navbar__brand via insertAdjacentElement('afterend', …).
  3. Adds has-post-title to .navbar__inner so the CSS can override .navbar__nav's margin-left: auto — the injected flex: 1 span takes over gap management.
  4. Creates an IntersectionObserver (threshold 0) on the <h1>. When the heading leaves the viewport, it adds navbar--title-visible to .navbar__inner; when it re-enters, it removes it.

CSS — .navbar__post-title is always flex: 1; min-width: 0 once injected, so it fills the gap between the brand and the nav links. It starts at opacity: 0; transform: translateY(4px); pointer-events: none. The navbar--title-visible modifier transitions it to opacity: 1; transform: translateY(0) with a $transition-normal duration. Hidden on mobile (display: none at ≤$bp-mobile) since the navbar is too compact for an extra text element. Styles live in _components.scss immediately after .navbar__title.

Diff code block highlighting

Fenced code blocks tagged with the diff language get per-line green/red visual markers for added and removed lines. No extra library is needed — Hexo's built-in highlight.js renderer already classifies +-prefixed lines as .hljs-addition and --prefixed lines as .hljs-deletion.

CSS — Both span classes in _code.scss use display: block to expand beyond inline width, margin: 0 -1rem to bleed to the edges of the code cell's pre padding, and padding: 0 1rem 0 calc(1rem - 3px) to compensate for a 3px left border stripe. This mirrors exactly the pattern already used by figure.highlight .marked (the manually marked-line feature). Color values:

  • .hljs-addition — background: rgba(16, 185, 129, 0.15) (green tint), border-left: 3px solid rgba(16, 185, 129, 0.7), color: #7ee8a2
  • .hljs-deletion — background: rgba(239, 68, 68, 0.12) (red tint), border-left: 3px solid rgba(239, 68, 68, 0.6), color: #ffa198

The border stripe is the key visual addition over a plain background: it gives an unambiguous edge marker, consistent with how most code review tools (GitHub, GitLab) render diff lines. Because the gutter (td.gutter) is a separate table column, per-line gutter coloring is not feasible without restructuring Hexo's table output — the left border on the code cell serves the same orientation purpose.

{% spoiler %} tag

A collapsible content block using the native HTML <details>/<summary> elements with theme-consistent styling. No JavaScript is required — open/close behavior is handled by the browser natively, including full keyboard accessibility (Enter/Space to toggle).

Tag registration — scripts/helpers.js registers spoiler as a Hexo block tag ({ ends: true }). All tag arguments are joined with spaces and HTML-escaped to form the summary label, defaulting to "Show spoiler" when no arguments are provided. The block body is passed through hexo.render.renderSync({ engine: 'markdown' }) with a try/catch fallback, identical to {% note %} and {% tabs %}. The output is a <details class="spoiler"> wrapping a <summary class="spoiler__summary"> and a <div class="spoiler__body">.

CSS — .spoiler has overflow: hidden to clip child content (code blocks, images) to the container's border-radius. The custom triangle indicator is a CSS ::before pseudo-element on .spoiler__summary: the default browser disclosure marker is suppressed via list-style: none (Firefox) and ::-webkit-details-marker { display: none } (Chrome/Safari), then replaced with a '▶' character that rotates 90° via transform: rotate(90deg) when details[open] is present. :focus-visible provides a keyboard-accessible outline. Styles live in _components.scss under // ─── Spoiler. See {% spoiler %} writing guide for syntax and examples.

CSS pipeline

All styles are written in SCSS and compiled by hexo-renderer-dartsass (Dart Sass). The entry point is themes/coldnight/source/css/style.scss, which @uses the partials in dependency order. Each partial declares its own variable dependency via @use 'variables' as *; at the top — no global imports, no implicit variable scope.

FileContents
_variables.scssAll color, spacing, typography, and breakpoint variables. Edit this file to retheme the entire site — every other partial reads from it. Font-stack variables ($font-sans, $font-mono) are unquoted SCSS lists — keep them unquoted or the compiler will treat the entire value as one unknown font name.
_base.scssCSS reset, body defaults, scrollbar styling, reduced-motion overrides (scroll-behavior: auto and animation: none under prefers-reduced-motion: reduce)
_typography.scssPost body typography — headings, lists, blockquotes, tables, inline code
_layout.scssPage shell grids (two-column, archive), post grid, archive list rows, archive filter chips, sidebar layout, .post-cover image, related-posts wrapper
_components.scssNavbar (including sticky post-title slot), footer, post cards, pinned hero, pagination, note callouts, tabs, timeline, spoiler, sidebar widgets, gallery grid, back-to-top button, reading progress bar, TOC widget, mobile TOC drawer, search dropdown
_code.scssCode block toolbar, language label, copy button hover state, diff line highlighting (.hljs-addition / .hljs-deletion with green/red background tints and left border stripes)
_lightgallery.scssLightGallery overrides to match the dark theme palette
💡

Never hardcode color values in partials — always reference a variable from _variables.scss. This ensures a single edit in _variables.scss recolors the whole theme consistently.
